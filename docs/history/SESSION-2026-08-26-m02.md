## What landed

### Backend — Dubbing pipeline (`backend/services/dubbing.py`)
Full orchestrated pipeline, reusing the m01 seams (Parakeet STT, pyannote diarization, LLM translation) and the existing TTS generation service:

```
extract → transcribe → diarize → merge → segment → translate → synthesize → assemble
```

- `create_project / list_projects / get / update_segment / resynthesize_segment` persistence helpers.
- `run_pipeline(project_id)` background runner with per-stage `status`/`stage` updates.
- Reuses `generation.generate_audio_sync` for per-segment TTS (default Kokoro) — voice assignment via speaker→profile mapping (falls back to first available profile; explicit error if none exists).
- `_assemble_track` places each segment's WAV on a canvas at the segment window; alignment/stretch hooks exist in the model for the `m03` pacing polish.

### Segmentation + length-fit (`backend/services/segmentation.py`)
- Ported from DUBBERc's proven math: `calculate_character_budget` (chars/sec per language ±12%) and `build_pause_aware_segments` (pause-threshold + max-duration + speaker-boundary grouping over word timestamps).

### Dubbing data model (`backend/database/models.py`)
- `dubbing_projects`, `dubbing_speakers`, `dubbing_segments` tables.

### Dubbing routes (`backend/routes/dubbing.py`)
- `POST /dubbing/projects` (multipart upload + project create), `GET /dubbing/projects`, `GET /dubbing/projects/{id}`, `POST /dubbing/projects/{id}/run`, `GET …/segments`, `PATCH /dubbing/segments/{id}`, `POST …/resynthesize`, `GET /dubbing/audio/{id}`.

### Frontend — Dubbing Studio (`app/src/components/Studio/DubbingTab.tsx`)
- New `/studio` route + Sidebar entry (Clapperboard, "Dubbing").
- Create-project form (file + source/target lang + STT engine), project list with status stages, project panel with Run Pipeline + assembled audio playback, segment editor (translate text, alignment start/center/end, lock, re-synthesize).
- **Pronunciation dictionary panel** (IPA) — list/add/delete, matching DUBBERc's Settings UX, wired to `/dictionary`.
- API client methods added to `@/lib/api/client` (dubbing + dictionary) following the existing fetch pattern.

### Pronunciation dictionary wiring (from m01, now surfaced in UI)
- Table + `/dictionary` CRUD + `apply_dictionary` phoneme hook are already in place; the Studio panel exposes it.
