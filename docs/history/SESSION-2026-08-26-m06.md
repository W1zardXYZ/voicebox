# Session 2026-08-26 — m06: dubbing pipeline fallback + local simulation

**Milestone:** m06-pipeline-robustness — make the dubbing/capture pipeline
degrade gracefully when the optional Parakeet/nemo engine is unavailable, and
let the dev machine (8 GB Apple M3 Max VM) run the *full* pipeline locally via
simulation — no model downloads.

## Problem
Running the dubbing pipeline crashed with `No module named 'nemo'` because:
1. `stt_engine` defaulted to **`parakeet`** (route + service), but `nemo-toolkit`
   is an optional, flaky-to-install dependency that wasn't present.
2. There was no fallback — requesting Parakeet with nemo missing raised
   `ModuleNotFoundError` and marked the project `failed`.

## Changes

### Backend — graceful STT engine resolution
- **`backend/services/transcribe.py`** — added `nemo_available()` (import-probe)
  and `resolve_stt_backend(engine) -> (backend, resolved_engine)`, which falls
  back to Whisper with a logged warning when Parakeet/nemo is unavailable.
- **`backend/services/dubbing.py`** — pipeline transcribe step now uses
  `resolve_stt_backend`; project `stt_engine` default relaxed to `whisper`.
- **`backend/services/captures.py`** — create/retranscribe dispatch uses
  `resolve_stt_backend` (same graceful fallback).
- **`backend/routes/dubbing.py`** + **`app/src/components/Studio/DubbingTab.tsx`**
  — default STT engine is now `whisper` (Parakeet opt-in).

### Testing on this machine (no model downloads)
- **`backend/tests/test_stt_engine_fallback.py`** (4) — resolve/fallback logic.
- **`backend/tests/test_dubbing_pipeline_simulation.py`** (2) — runs the REAL
  `run_pipeline` end-to-end (extract → transcribe → diarize → segment →
  translate → synthesize → assemble) against a real SQLite DB and synthetic
  WAV, with only the model-boundary calls (STT, diarization, translation, TTS
  synthesis) faked. Reaches `status == "ready"` and writes a `master_16k.wav`.
  This is the substitute for the heavy ML stack on this 8 GB box.
